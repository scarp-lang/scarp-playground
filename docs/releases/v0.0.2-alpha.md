# Scarp Playground v0.0.2 (alpha)

**Experimental pre-release — not stable or a security-hardened sandbox.**

Try the current development preview: https://scarp-lang.github.io/scarp-playground/

This alpha packages the verified website as a standalone archive with a
SHA-256 checksum. It captures the source and the Rust/WASM compiler at this
release tag; the live `main` website may subsequently change.

## Exact compiler compatibility

- **Official Scarp compiler:** v0.0.5-alpha.4
- **Compiler source revision:** `79141329176f5dce51457e90a6652902f6432135`
- **Execution:** Official interpreter compiled to WebAssembly, in a disposable
  browser Worker with deterministic interpreter work budgets and a 12-second
  browser deadline. No server evaluates code.
- **Not supported:** The upstream host-filesystem `Scarp.project` CLI
  create/launch/verify commands are not exposed by the in-memory browser runtime.

## New since the v0.0.1 alpha

- More responsive Monaco loading: Scarp-specific ESM editor bundle, separate
  file models, persistent undo history and improved loading boundaries.
- Real source-aware compiler diagnostics: schema-1 file locations, clickable
  imported-module errors, related locations, Unicode-scalar to Monaco UTF-16
  column translation, and stale marker clearing.
- Multi-file **Save locally** with explicit opt-in and deletion, preserving
  editor tab state. Browser storage is unencrypted and never synchronized.
- Portable, versioned multi-file **JSON export/import**, validated for source
  paths and bytes. Import does not automatically replace locally saved projects.
- **Stop run** plus revision-scoped cancellation: changing source, entrypoint or
  project terminates an older Worker and rejects late output or diagnostics.
- Upgrade from Scarp alpha.3 to the independently verified **alpha.4** exact
  compiler commit, with real WASM and browser execution regression tests.
- Stronger Worker protocol: a 1 MiB raw Rust request limit, bounded compiler
  reply JSON and diagnostics, a 1 MiB combined stdout/stderr UTF-8 ceiling,
  and controlled handling of malformed messages and Worker cloning errors.

## Compatibility and quality gate

The alpha release pipeline runs pinned `npm ci`, lint, type-checking, frontend
unit tests, native Rust tests, locked `wasm-pack` compilation, a production
bundle and the full real Chromium execution suite **before** packaging and
publishing the static website archive. The associated `.sha256` file lets you
verify archive integrity. The release and both assets are never overwritten.

## Known limitations and security notice

- No native Scarp executable generation, source-code networking, real filesystem
  access, backend execution endpoint, installed packages or cloud workspace sync.
- Short `#code=` URLs only share a **single** source file; multi-file projects
  use local JSON import/export.
- WASM Worker timeouts and interpreter budgets do **not** establish independent
  process memory isolation, hostile-source safety or a hardened browser sandbox.
  Heavy or adversarial code could exhaust browser memory. Do not paste secrets.
- Only Chromium is covered by the automated end-to-end suite. Wider browser,
  accessibility and independent security assessments remain pending.
- The first Playground `v0.0.1` release is unchanged; this alpha is additive.

**Stable release policy:** Do not publish Playground v1.0.0 until Scarp reaches
its own first stable release and the Playground passes independent security,
compatibility, accessibility and quality review.
